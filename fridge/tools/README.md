# 개발용 도구

앱에 포함되지 않는다. 배포에도 올라가지 않는다.

## nutrition.py — 영양정보 계산

레시피 1인분 영양정보를 계산한다. 칼로리를 눈대중으로 적으면 실제와 60% 넘게
어긋나므로 손으로 적지 않는다.

```bash
python3 tools/nutrition.py ../recipes.json   # 현재 값과 계산 값 비교
```

`recipes.json` 에 반영하려면 `compute()` 를 불러 `calories` 와 `nutrition` 을 덮어쓴다.
결과는 10 단위로 반올림한다 — 어림값임을 숫자 모양으로 드러내기 위함이다.

### 계산 순서 — 실측값을 먼저 찾고, 없으면 재료를 더한다

1. **요리명이 `dish_nutrition_db.csv` 와 정확히 일치하면 그 실측/산출값을 쓴다.**
   여러 출처가 있으면 `가정식(분석 함량) > 외식(분석함량) > 재료량 기반 산출 > 프랜차이즈 제공`
   순으로 가장 믿을 만한 것을 고른다. 1인분 무게는 레시피 재료 총량을 인분 수로 나눠 구하고,
   그 무게에 DB의 100g당 값을 비례시킨다
2. **일치하는 이름이 없으면** 재료마다 `NUTRI` 표의 100g당 값 × 용량을 더해 추정한다

1번이 2번보다 훨씬 정확하다. 실측값에는 조리 중 수분 증발 같은 손실이 이미
반영돼 있는데, 재료를 단순히 더하기만 해서는 그걸 알 수 없다. 미역국이 그 예다 —
재료 합산으로는 170kcal 가 나왔지만 실측값은 49kcal 였다. 물을 얼마나 졸이는지는
재료 목록에 안 적히기 때문이다.

### dish_nutrition_db.csv — 식약처 식품영양성분 DB(음식)

[식품안전나라](https://various.foodsafetykorea.go.kr/nutrient/) 에서 받은 음식 19,495건 중
필요한 열만 뽑은 것이다. 원재료가 아니라 **조리된 음식**의 100g당 실측/산출값이므로
요리명이 일치할 때만 쓸 수 있다. 새 원본을 받으면 이 파일을 다시 만든다
(`식품명·식품대분류명·영양성분함량기준량·에너지(kcal)·탄수화물(g)·단백질(g)·지방(g)·나트륨(mg)·식품기원명`
열만 남기고 CSV로 저장).

### NUTRI 표 — 실측값이 없을 때의 대체 재료 영양가

재료 100g당 (열량/탄수/단백/지방). 식품성분표의 통상값이며, 이름이 DB와 안 맞는
외국 요리·창작 요리에 쓰인다. 재료 낱개(당근·양파 등) 영양가는 이 DB에 없으므로
이 표는 계속 유지한다.

### 알아둘 것

- 튀김 기름은 붓는 양이 아니라 **흡수량(재료 무게의 10%)** 으로 잡는다.
  이 보정이 없으면 튀김 요리가 3000kcal 로 나온다
- `NUTRI` 에도 없는 재료가 있으면 계산이 실패한다. 조용히 0 으로 넘어가지 않는다
- 값은 어림값이다. 완성품 칼로리는 공개 출처끼리도 2배씩 차이가 난다.
  실측값을 썼든 재료로 추정했든, "무엇에 근거했는지"는 남지만 정밀 측정은 아니다
